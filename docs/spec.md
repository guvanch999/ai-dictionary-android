# Спецификация проекта: AI-словарь пользователя (Android)

**Рабочее название:** Sözlük AI (уточняется)
**Версия документа:** 0.1 — черновик для обсуждения
**Дата:** 22.08.2026
**Платформа:** Android (нативно). iOS — вне рамок данной версии.

---

## 1. Обзор и цель

Персональный словарь с AI-объяснениями. В отличие от классического словаря, база изначально пуста: пользователь сам добавляет слова, которые встретил и не понял. Приложение через Anthropic API объясняет слово на английском, переводит на родной язык пользователя, приводит примеры употребления и сохраняет всё локально. Накопленные слова становятся материалом для персональных экзаменов (квизов), которые генерирует AI.

Ключевая идея: словарь отражает реальные пробелы конкретного человека, а экзамены закрепляют именно те слова, которые он искал.

### 1.1 Целевая аудитория

Изучающие английский язык, родной язык — русский или туркменский. Первичный пользователь — сам автор проекта; публикация в Google Play рассматривается как этап 2.

### 1.2 Не входит в объём (out of scope) v1

- iOS-версия.
- Синхронизация между устройствами и аккаунты.
- Офлайн-объяснения (без сети доступен только просмотр сохранённых слов и локальные квизы).
- Социальные функции, общие словари, рейтинги.

## 3. Роли AI и безопасность ключа

### 3.1 Использование API

Все объяснения, переводы, генерация квизов и распознавание слов на изображениях выполняются через Anthropic API. Запросы формулируются так, чтобы ответ был **строго валидным JSON** без Markdown — ответы парсятся в типизированные модели.

Разделение по моделям:

- **Словарная статья** (объяснение + перевод + примеры) — лёгкая модель (Haiku): дёшево, быстро, задача шаблонная.
- **Генерация экзамена** — более сильная модель (Sonnet): нужны разнообразные, нетривиальные задания.
- **Чтение слова с изображения** (fallback после ML Kit) — модель со зрением (Sonnet), на вход подаётся кроп скриншота.

### 3.2 Хранение ключа

В v1 (личное использование) ключ **не зашивается в APK**. Пользователь вводит ключ один раз на экране настроек; ключ хранится в `EncryptedSharedPreferences` (Android Keystore). В коде выделяется интерфейс `AiClient`, чтобы при публикации заменить прямые вызовы API на собственный прокси-бэкенд (Cloudflare Workers / Vercel) без переписывания приложения.

### 3.3 Экономия запросов

- Перед запросом к API — проверка в локальной БД: если слово уже сохранено (с тем же контекстом/значением), показывается сохранённая статья. Кнопка «Обновить через AI» доступна вручную.
- Квизы генерируются **пакетом** (10–15 слов за один запрос), а не по одному.
- Часть типов квизов генерируется локально без AI (см. §7.2).

## 4. Модель данных

### 4.1 Сущность WordEntry

| Поле | Тип | Описание |
|---|---|---|
| id | String (UUID) | первичный ключ |
| term | String | само слово или фраза |
| normalizedTerm | String | нижний регистр, трим — для поиска и дедупликации |
| sourceLang | String | язык слова, по умолчанию `en` |
| explanationEn | String | объяснение простым английским (CEFR ~B1) |
| translationRu | String | перевод на русский |
| translationTk | String | перевод на туркменский (латиница) |
| partOfSpeech | String? | часть речи |
| ipa | String? | транскрипция |
| synonymsJson | String | JSON-массив синонимов |
| examplesJson | String | JSON-массив `{en, ru, tk}` |
| commonMistake | String? | типичная ошибка / ложный друг |
| contextSentence | String? | предложение-источник (из выделения или скриншота) |
| sourceType | Enum | MANUAL / PROCESS_TEXT / SCREENSHOT |
| imagePath | String? | путь к кропу скриншота, если был |
| createdAt | Long | время добавления |
| **Поля повторения (SRS):** | | |
| box | Int | ячейка Лейтнера 0–5 |
| nextReviewAt | Long | когда слово снова попадает в экзамен |
| correctCount / wrongCount | Int | статистика ответов |
| consecutiveCorrect | Int | верных ответов подряд (ошибка сбрасывает в 0) |
| status | Enum | LEARNING / MASTERED — усвоенные слова почти не попадают в экзамены (§7.5) |

### 4.2 Сущности экзамена

- **ExamSession**: id, createdAt, wordIds (JSON), режим, итоговый счёт, состояние (в процессе / завершён) — чтобы экзамен переживал закрытие приложения.
- **QuizItem**: id, sessionId, wordId, type, payloadJson (вопрос/варианты/ответ/объяснение), userAnswer, isCorrect.

### 4.3 Дедупликация

При добавлении слова ищется совпадение по `normalizedTerm`. Если найдено — показывается существующая карточка с предложением: «открыть сохранённое» или «это другое значение — запросить заново с новым контекстом» (тогда создаётся вторая запись с иным `contextSentence`).

## 5. Функциональные требования

Формат: **F-N** — требование, приоритет (P0 обязательное для v1, P1 желательное, P2 позже).

### F-1. Добавление и объяснение слова — P0

1. Пользователь вводит слово вручную на главном экране (или оно приходит из F-5/F-6).
2. Приложение показывает состояние загрузки и отправляет запрос AI. В запрос включается `contextSentence`, если он есть — объяснение должно соответствовать значению слова **в этом контексте**.
3. Ответ — словарная статья: объяснение на английском, перевод (ru + tk одновременно, см. §8.3), часть речи, транскрипция, 2–3 примера с переводом, синонимы, типичная ошибка.
4. Статья автоматически сохраняется в БД. Повторный запрос по тому же слову API не трогает.
5. Ошибка сети / API → понятное сообщение и кнопка «Повторить»; введённое слово не теряется (попадает в очередь «ожидают объяснения», добивается через WorkManager при появлении сети).

### F-2. Список слов и поиск — P0

1. Главный экран — список сохранённых слов: слово, краткий перевод, дата.
2. Мгновенный локальный поиск по мере ввода (по term и переводам).
3. Если запрос не найден в базе — та же строка поиска предлагает «Спросить AI» (переход в F-1). Поиск и добавление — одно поле, без отдельных экранов.
4. Сортировка: по дате / по алфавиту / «слабые слова» (по статистике ответов).
5. Свайп или меню: удалить, отредактировать вручную, обновить через AI.
6. Карточка слова открывается на весь экран со всей статьёй; кнопка озвучки (TTS).

### F-3. Экзамен — P0

1. Пользователь запускает экзамен и выбирает: количество вопросов (10 / 20 / все к повторению), охват слов (все / за неделю / только слабые / к повторению по SRS).
2. Приложение собирает пул слов, часть заданий генерирует локально, часть — одним пакетным запросом к AI (см. §7).
3. Вопросы показываются по одному; после ответа — мгновенная обратная связь: верно/неверно + короткое объяснение.
4. В конце — итог: счёт, список ошибок со ссылками на карточки слов.
5. Результаты обновляют SRS-поля слов (ячейка Лейтнера, nextReviewAt, consecutiveCorrect): верный ответ двигает слово вверх, ошибка сбрасывает в ячейку 1. Слова с серией верных ответов постепенно вытесняются из экзаменов, а усвоенные — исключаются почти полностью (§7.5).
6. Незавершённый экзамен восстанавливается при следующем запуске.

### F-4. Открытые задания с проверкой AI — P1

Тип задания «составь своё предложение с этим словом»: ответ пользователя отправляется AI, тот возвращает вердикт (естественно / есть ошибка), исправление и краткий комментарий на языке интерфейса.

### F-5. Кнопка в меню выделения текста — P0

1. Приложение регистрирует activity с `ACTION_PROCESS_TEXT` (mime `text/plain`) — Android сам добавляет пункт в системное меню выделения (рядом с Copy / Select all) в любых приложениях, где текст выделяем.
2. По нажатию открывается **прозрачная activity с компактной карточкой** поверх текущего приложения — пользователь не покидает читалку/браузер.
3. Если выделено одно слово — оно уходит в F-1 как есть. Если выделено предложение — показывается предложение, пользователь тапает нужное слово в нём; предложение сохраняется как `contextSentence`.
4. Название пункта меню локализовано (`android:label` из ресурсов).
5. В карточке — кнопка «Открыть в приложении» для полной статьи.

### F-6. Скриншот + обводка + OCR — P1

Для мест, где текст нельзя выделить (изображения, защищённые сайты, видео).

1. **Перехват долгого нажатия Power технически невозможен** — Android не даёт приложениям хук на системный скриншот. Вместо этого: фоновый наблюдатель (`ContentObserver` на `MediaStore.Images` в foreground service) замечает новый файл в папке Screenshots.
2. При обнаружении скриншота поверх экрана всплывает ненавязчивый пузырь «✏️» (SYSTEM_ALERT_WINDOW). Игнорируется — исчезает через ~6 секунд.
3. Тап по пузырю → полноэкранный редактор: скриншот + рисование пальцем. Пользователь обводит слово или предложение.
4. По bounding box обводки (с запасом ~15% по краям — для контекста) делается кроп.
5. Кроп сначала идёт в **ML Kit** (on-device OCR, бесплатно, офлайн). Распознан текст → обычный поток F-1 (окружающий текст кропа — как contextSentence).
6. ML Kit не справился (стилизованный шрифт, рукописный текст) → кроп отправляется **изображением в Claude**, модель читает и сразу объясняет. Кроп сохраняется в `imagePath` слова.
7. Наблюдатель включается/выключается тумблером в настройках; по умолчанию выключен, при включении — онбординг с объяснением разрешений.
8. Альтернативный вход в тот же редактор: «поделиться изображением» в приложение (`ACTION_SEND image/*`) — работает без всяких фоновых сервисов и разрешений. Реализуется в первую очередь, наблюдатель — во вторую.

### F-7. Настройки — P0

- API-ключ Anthropic (ввод, проверка тестовым запросом, хранение в EncryptedSharedPreferences).
- Язык интерфейса: русский / туркменский / английский (+ «как в системе»).
- Родной язык для акцента в карточке: ru / tk (какой перевод показывать первым; хранятся оба).
- Тумблер наблюдателя скриншотов (F-6).
- Статистика: всего слов, слов к повторению, история экзаменов.
- Экспорт/импорт базы в JSON-файл (страховка от потери данных) — P1.

## 6. Контракты с AI

### 6.1 Словарная статья

Системный промпт (суть): «Ты движок словаря. Верни ТОЛЬКО валидный JSON без Markdown по схеме… Объяснение — простой английский уровня B1. Переводы на Russian и на Turkmen (Latin script, türkmen dili — не турецкий). Если дан context sentence — объясняй значение, использованное именно там.»

Схема ответа:

```json
{
  "term": "bank",
  "partOfSpeech": "noun",
  "ipa": "/bæŋk/",
  "explanationEn": "The land along the side of a river...",
  "translationRu": "берег",
  "translationTk": "kenar",
  "synonyms": ["shore", "riverside"],
  "examples": [
    {"en": "We had a picnic on the river bank.",
     "ru": "Мы устроили пикник на берегу реки.",
     "tk": "Biz derýanyň kenarynda piknik etdik."}
  ],
  "commonMistake": "Не путать со значением 'банк' (financial institution)."
}
```

Парсинг устойчивый: срезать возможные ```json-ограждения, при невалидном JSON — один автоматический повторный запрос, затем ошибка пользователю.

### 6.2 Пакет квизов

На вход: список слов с переводами и контекстами, желаемые типы заданий, язык интерфейса (для формулировок и объяснений). На выход — массив:

```json
[{
  "type": "gap_fill",
  "wordId": "…",
  "question": "I need to ___ my English before the exam.",
  "options": ["improve", "improvise", "prove", "approve"],
  "answerIndex": 0,
  "explanation": "…"
}]
```

Валидация на клиенте: answerIndex в границах, options без дублей, question не пустой. Невалидный элемент выбрасывается и заменяется локально сгенерированным заданием — экзамен не падает из-за одного плохого вопроса.

### 6.3 Проверка открытого ответа (F-4)

Вход: слово, статья, предложение пользователя. Выход: `{verdict: "ok|minor|wrong", corrected, comment}` — comment на языке интерфейса.

## 7. Движок квизов

### 7.1 Принцип

Экзамен — смесь локальных и AI-заданий. Соотношение примерно 40/60, при отсутствии сети — 100% локальных (экзамен работает офлайн).

### 7.2 Локальные типы (без AI)

- слово → выбрать перевод из 4 (обманки — переводы других слов пользователя);
- перевод → выбрать слово из 4;
- собрать слово из перемешанных букв;
- аудио (TTS произносит) → выбрать слово;
- показанный ранее пример с закрытым словом → вписать/выбрать.

Требование к обманкам: та же часть речи, сопоставимая длина, не синонимы правильного ответа.

### 7.3 AI-типы

- новое предложение с пропуском (gap fill) — не совпадает с примерами из карточки;
- определение на английском → угадать слово;
- предложение с ошибкой употребления → найти и исправить;
- выбор синонима, подходящего по контексту;
- мини-диалог с 2–3 пропусками на разные слова;
- открытое «составь предложение» (F-4).

### 7.4 SRS (интервальные повторения)

Упрощённый Лейтнер: 6 ячеек, интервалы 0 / 1 / 3 / 7 / 16 / 35 дней. Режим экзамена «к повторению» берёт слова с `nextReviewAt <= now`. На главном экране — бейдж «N слов ждут повторения».

### 7.5 Вытеснение выученных слов из экзаменов

Слова, на которые пользователь несколько раз подряд ответил верно, должны появляться в экзаменах редко, а полностью усвоенные — почти никогда.

**Отбор слов в экзамен — взвешенная выборка**, а не равномерная. Вес слова:

| Состояние | Условие | Вес в выборке |
|---|---|---|
| Новое / проблемное | box 0–1 или недавняя ошибка | ×4 |
| Изучается | box 2–3 | ×2 |
| Почти усвоено | box 4–5, consecutiveCorrect < порога | ×1 |
| **Усвоено (MASTERED)** | см. ниже | ×0.1 (~1 слово на 2–3 экзамена, только контрольная проверка) |
| Просрочено к повторению | nextReviewAt <= now | вес умножается ещё на ×2 |

**Переход в MASTERED:** `consecutiveCorrect >= 5` **и** box == 5 (т.е. слово пережило и серию верных ответов, и длинные интервалы — одной сессии зубрёжки недостаточно). Любая ошибка мгновенно возвращает статус LEARNING, сбрасывает consecutiveCorrect в 0 и опускает слово в ячейку 1 — оно снова начинает часто попадать в экзамены.

**Контрольные проверки:** усвоенные слова не исчезают навсегда — с весом ×0.1 они изредка всплывают, чтобы подтвердить, что слово не забыто. Это защита от «выучил и забыл через полгода».

**Нюанс подсчёта серии:** если одно слово встретилось в экзамене дважды (например, gap fill и аудио), верные ответы в рамках одной сессии увеличивают consecutiveCorrect максимум на 1 — иначе слово «усвоится» за один экзамен.

**UI:** в списке слов у усвоенных — метка ✓; фильтр «показать усвоенные»; на экране настройки экзамена — тумблер «включить усвоенные слова» для тех, кто хочет прогнать всё. В статистике (F-7) — счётчик «усвоено X из Y».

## 8. Локализация (3 языка)

### 8.1 Механика

`strings.xml` в `values/` (en, базовый), `values-ru/`, `values-tk/`. Переключение языка внутри приложения через `AppCompatDelegate.setApplicationLocales` (per-app language, работает с API 26+ через autoStoreLocales).

### 8.2 Два независимых языка

«Язык интерфейса» и «родной язык переводов» — отдельные настройки. Пример: туркменский UI + объяснения на английском + перевод первым показывается туркменский, русский — под ним.

### 8.3 Туркменский

- В промптах всегда явно: *Turkmen, Latin script (türkmen dili)* — иначе модель может уйти в турецкий.
- Переводы запрашиваются сразу на оба языка (ru + tk) и хранятся оба: русский служит подстраховкой, т.к. качество туркменского у моделей ниже.
- Все строки UI на tk вычитываются носителем перед релизом.

## 9. Разрешения

| Разрешение | Зачем | Когда запрашивается |
|---|---|---|
| INTERNET | API | установка |
| POST_NOTIFICATIONS | уведомление foreground-сервиса, напоминания SRS | при включении соответствующих функций |
| READ_MEDIA_IMAGES | чтение новых скриншотов (F-6) | при включении наблюдателя |
| SYSTEM_ALERT_WINDOW | пузырь-карандаш поверх экрана (F-6) | при включении наблюдателя |
| FOREGROUND_SERVICE (+ тип) | наблюдатель скриншотов | при включении наблюдателя |

Принцип: без F-6 приложение работает вообще без опасных разрешений.

## 10. Нефункциональные требования

- **Отклик UI:** локальный поиск < 50 мс на 10 000 слов; карточка из БД открывается мгновенно.
- **AI-запросы:** таймаут 30 с, 1 автоповтор при сетевой ошибке; всегда видимое состояние загрузки и отмена.
- **Офлайн:** просмотр слов, локальный поиск, локальные квизы — полностью без сети; добавления встают в очередь.
- **Данные:** все данные локальны; наружу уходят только тексты слов/предложений и кропы изображений в Anthropic API. Это фиксируется в экране «О приложении».
- **Стоимость:** целевой ориентир — типичная словарная статья через Haiku и пакетная генерация квизов; счётчик потраченных запросов в настройках (P1).
- **Тесты:** unit — парсинг JSON-ответов, генератор локальных квизов, логика SRS; инструментальные — DAO Room.

## 11. Экраны (v1)

1. **Главный** — поиск/добавление + список слов + бейдж повторений + кнопка «Экзамен».
2. **Карточка слова** — полная статья, TTS, редактирование, удаление, «обновить через AI».
3. **Настройка экзамена** — количество, охват, старт.
4. **Экзамен** — вопрос, прогресс, мгновенный фидбек.
5. **Результаты** — счёт, разбор ошибок.
6. **Popup-карточка** (прозрачная activity для F-5).
7. **Редактор скриншота** (F-6).
8. **Настройки** и первый запуск (онбординг: ввод ключа, выбор языков).

## 12. План работ (этапы)

| Этап | Содержание | Результат |
|---|---|---|
| M1 | Каркас проекта, Room, AiClient со словарной статьёй, главный экран, карточка слова, настройки с ключом | можно добавлять и смотреть слова |
| M2 | ACTION_PROCESS_TEXT + прозрачная карточка (F-5); ACTION_SEND для изображений + редактор обводки + ML Kit (упрощённый вход в F-6) | добавление слов из любого приложения |

| M5 | Наблюдатель скриншотов + пузырь (полный F-6), проверка открытых ответов (F-4), счётчик расходов | расширенная версия |
| M6 (опц.) | Прокси-бэкенд для ключа, подготовка к Google Play | публикация |

## 13. Риски

1. **Ключ в клиенте** — приемлемо только для личного использования; перед любой раздачей APK обязателен прокси (M6).
2. **Наблюдатель скриншотов** — поведение MediaStore и фоновых сервисов различается между Android 13/14/15 и прошивками (MIUI, Samsung); поэтому основной вход в F-6 — через «Поделиться», наблюдатель — надстройка.
3. **Google Play** — SYSTEM_ALERT_WINDOW и чтение медиа потребуют обоснования в анкете; AccessibilityService сознательно не используется.
4. **Качество туркменского** у моделей — смягчается двойным переводом (ru + tk) и явным указанием языка в промпте.
5. **Невалидный JSON от модели** — смягчается повтором запроса и заменой битых квиз-элементов локальными.
